# 番茄短篇 · 去 AI 味写作 Skill

> 一个给 AI Agent / 大模型用的**番茄短故事**写作技能包：从选题、开篇、结构、反转、标题简介，到两遍式去 AI 味和机器扫描，全部拆成可执行的步骤。
>
> 目标不是“骗过 AIGC 检测”，而是让文本**具体、有代价、有活人声音**。

**仓库**：<https://github.com/jinne342/fanqie-short-story>

## 这是什么

一个「写作方法 + 去味手册 + 可执行检查器 + 名著技法库 + 对照案例」的 Skill：

- **写前**：锁定主情绪、赌注、反转与代价，避免“设定很好，故事没发生”。
- **写中**：按 6000 / 1.2 万 / 1.8 万字节拍推进，每节一个主问题、一次变盘。
- **写后**：先跑 `check_ai.py` 清“形”，再做语义十问和朗读，清“神”。
- **仿写**：内置 100 本名著技法种子卡 + 本地 1000 本原文索引工具；先检索 3 张卡，再“换表面、留功能”，不抄句子。
- **跨环境**：Agent 工具、网页聊天、纯聊天、API 流水线四种运行形态；没有工具就不伪造扫描结果。
- **跨模型**：`prompt.md` 是一份可直接贴进 ChatGPT / Claude / Gemini 的便携系统提示词。

适用于番茄短故事（≥6000 字可签约，1 万–1.8 万字是爆款/短剧改编主流区间），也适用于七猫、盐言等同类通俗短篇；平台规则部分以番茄为基线。

## 为什么不是“AI 检测器”

AI 味不是几个词，而是四种默认选择：

| 来源 | 表现 | 人味的方向 |
|---|---|---|
| 均匀 | 段一样长、句一样长、每节节奏一样 | 长短交错，该短则短 |
| 解释 | 每个情绪都命名，每个动作都解释 | 让动作和物件说话 |
| 安全 | 比喻用“水/火/风”，冲突用“误会—解释—和好” | 具体、意外、角色化 |
| 无偏见 | 叙述者像摄像机，人物一个腔调 | 有立场、有盲区、有说不出口的话 |

所以这个 Skill 的重心是**换掉信息组织方式**，不是同义词替换，更不是加错别字。检查器只负责找“形”，语义判断仍然要人来做。

## 它怎么工作

```
定参数 → 一句话故事核 →（仿写时）名著检索 → 节拍大纲 → 逐节写 → 机械遍 → 语义遍 → 朗读遍 → 四道终检
```

- **机械遍**：`check_ai.py` 找模板句、情绪直述、套式动作、比喻密度、均匀段长、结尾升华、工程词泄漏。
- **语义遍**：逐节问十个问题——谁想要什么、做了什么选择、什么变了、哪个细节只有这篇有、叙述者的偏见在哪。
- **朗读遍**：出声读，卡住的地方就是该改的地方；删掉 10% 的形容词、解释和重复情绪。

## 快速开始

### 0. 获取代码

```bash
git clone https://github.com/jinne342/fanqie-short-story.git
cd fanqie-short-story
```

### 方式一：DSH / 支持 Skill 的 Agent

把整个目录复制到用户技能目录：

```powershell
# Windows
Copy-Item -Recurse . "$HOME\.dsh\skills\fanqie-short-story"
```

```bash
# macOS / Linux
mkdir -p ~/.dsh/skills
cp -R . ~/.dsh/skills/fanqie-short-story
```

或在仓库根目录运行安装脚本：

```powershell
.\install.ps1
```

```bash
./install.sh
```

然后直接说：

> 用番茄短篇 skill 写一篇世情反转，1.2 万字。
>
> 帮我把这篇去 AI 味，先跑扫描器，再按语义十问改。
>
> 只诊断这篇短篇，给我平台门/故事门/人味门三张单。
>
> 像张爱玲那样写一个开头，但写县城相亲角，不要上海腔。
>
> 把我 D 盘的书建成名著索引，然后按“雨、葬礼、冷眼”找 5 段参考。

### 方式二：普通聊天模型

把 [`prompt.md`](prompt.md) 整段贴进系统提示或对话开头。它不含本地脚本，但包含同一套写作规则。

### 方式三：API 两段式流水线

1. 第一次调用：生成正文。
2. 本地跑 `check_ai.py`，把报告和正文一起给第二次调用，要求“只改阻断项，不改人物动机和关键证据”。

不要一次让模型“边写边自查”，它会把故事改成检查表。

## 跨环境怎么跑

同一个 skill，不同环境的能力不一样。先判断四件事：能不能读文件、跑 Python、写文件、单次输出多少字。

| 环境 | 做法 |
|---|---|
| Agent + 工具（DSH / Claude Code / Codex） | 分节落盘，每节跑 `check_ai.py`，最后合并终检 |
| 聊天 + 文件上传 | 用 `prompt.md` + `04-checklist.md` 手工清单，不报分数 |
| 纯聊天（无工具） | 先给 7 拍大纲，每次 1500–2500 字，让用户回“继续” |
| API 流水线 | 生成 → 本地扫描 → 定向改写，两次调用分离 |

细节见 [`references/05-runtime-adapters.md`](references/05-runtime-adapters.md)。

## 名著库：100 本种子 + 1000 本索引

先把话说清楚：**没有任何模型能把 1000 本全文同时装进上下文。** 这个 skill 不“背全文”，而是三层记忆：

| 层 | 规模 | 存在哪 | 作用 |
|---|---|---|---|
| L0 种子地图 | 100 本 | `assets/classics-seed.json` | 永远可用；每本一条“可偷的一招” |
| L1 风格卡 | 100–1000 本 | 用户自己写/生成 | 每本一页：视角、句长、对话比、意象、开篇/结尾 |
| L2 原文索引 | 约 1000 本 | 本地 SQLite（不发布） | 按关键词检索原文段落，取 top-k |

每次只取 **3–5 段 / 3 张卡**；上下文里不堆全书。

> 当前 L2 是**关键词 / trigram** 检索，适合“雨、葬礼、冷眼”这类具体词；如果你想按“那种潮湿的、什么都晚一步的感觉”这种抽象描述检索，需要再接 embedding（Roadmap 里）。

### 没有原文库：查 100 本种子卡

```bash
python scripts/classics_index.py seed --query "冷眼 婚姻 开头" --limit 5
```

输出是“书名 + 可偷的一招”，不是情节简介。例：

```text
1. 《孔乙己》鲁迅 [视角]
   可偷：小伙计视角，冷眼看、不解释，留白即批判。
2. 《倾城之恋》张爱玲 [人物]
   可偷：白流苏出场在娘家客厅的算计里，婚姻市场即人物处境。
```

### 有原文库：建 1000 本索引

```bash
# 支持 .txt / .md / .docx；索引只存本地
python scripts/classics_index.py build --source "D:\books" --index "D:\books\classics.sqlite"

python scripts/classics_index.py query \
  --index "D:\books\classics.sqlite" \
  --query "雨 葬礼 冷眼" --limit 5

python scripts/classics_index.py stats --index "D:\books\classics.sqlite" --top 10
```

### 仿写：三步，不是洗稿

1. **检索 3 张卡**，每张只取 1 个动作（开场 / 视角 / 句长 / 物件 / 对话 / 结尾）。
2. **换表面、留功能**：人物、地点、时代、事件至少换两样；保留信息给的早晚、叙述距离、节奏和收法。
3. **反抄检查**：

```bash
python scripts/classics_index.py similarity \
  --index "D:\books\classics.sqlite" \
  --file 正文.txt --threshold 12 --strict
```

12 字以上连续重合必须改；只换同义词不算改。交付时标注：

```text
【结构参考】X《书名》的“物件开场 + 冷眼反讽”；不复用其句子、专名、情节链。
```

完整方法、卡片模板、六个“快速反应”配方见 [`references/06-classics-library.md`](references/06-classics-library.md)。一个“县城相亲角”的完整仿写示例见 [`examples/classics-demo.md`](examples/classics-demo.md)。

> 版权边界：原文索引只放本地；仓库只放技法摘要和 100 本种子卡，不放版权文本。仿写只搬工序，不搬表达。

## 检查器

零依赖，Python 3.10+：

```bash
python scripts/check_ai.py 正文.txt --min-words 6000
python scripts/check_ai.py 正文.txt --json
python scripts/check_ai.py 正文.txt --strict
python scripts/check_ai.py 正文.txt --sections
```

输出示例：

```text
====================================================
番茄短篇 · 模板腔扫描
====================================================
文件      examples/case-01/ai-draft.txt
字数      458（非空白）
段落      8    对话行 2
指数      25/100    等级 D
字数门    通过（≥0）
----------------------------------------------------
[阻断] 结尾升华/预告 ×4（-15）
[阻断] 不是A而是B ×1（-12）
[建议] 套式动作 ×5（-15）
[建议] 解释链 ×6（-12）
[建议] 情绪直述 ×3（-12）
[建议] 弱化副词偏多 ×5（-9）
```

- **阻断**：固定模板句、结尾升华、工程词泄漏、标点连用等，建议清零。
- **建议**：密度型或语义型问题，按“删掉是否损失信息”逐条判断。
- **白名单**：同目录 `.deslop-whitelist`，一行一个字面片段，`#` 开头为注释；只放作者明确要保留的句子。
- **分数**：100 分制，≥85 A，75–84 B，60–74 C，<60 D；`--strict` 在阻断或 <75 时退出 1。

> 这是风格体检，不是 AIGC 检测器；分数不承诺过稿，平台审核看整体质量。

## 实测

同一场“满月宴陪嫁房”：

- `ai-draft.txt`：**25/100 D**，2 类阻断（“不是 A 而是 B”、结尾“这一切才刚刚开始”），4 类建议。
- `human-draft.txt`：**100/100 A**，714 字样章，无阻断项。
- 用一篇 1.8 万字的同人番外做回归：**93/100 A**，只剩“连续短句”一条建议（有意的排比节奏；该文为本地测试稿，未收录）。
- 名著库管线：100 条种子卡、3 本测试库的 build/query/similarity 全部通过；12 字以上重合会触发 `--strict` 退出 1。

对照案例见 [`examples/case-01/notes.md`](examples/case-01/notes.md)。

## 平台事实（2026-11）

写之前先知道“为谁写、写到多长、什么不能碰”：

- 番茄短故事签约门槛 **≥6000 字**；6000–24999 字为超短篇/短篇；**1 万–1.8 万字**是爆款与短剧改编主流区间；2.5 万–8 万为中短篇。
- 开篇 **300–500 字**必须抛出核心困境或反转；标题按“人设 + 冲突 + 悬念”，简介按“身份钩 + 转折 + 爽点预期 + 尾钩”。
- 2026 年 9 月起新增**完本签约**、提高签约标准，万字读完率、评分、有效追更的考核更硬。
- 2026 年上半年平台专项治理低质 AI 文；“AI 粗制滥造”与格式混乱、结构失常、空洞水文并列。
- 同人无授权不能签约；校园暴力、灵异恐怖、犯罪过程要克制处理。

详细来源与可靠度标注见 [`references/01-platform-2026.md`](references/01-platform-2026.md)。政策会变，投稿前以作家助手后台当天公告为准。

## 设计原则

1. **先情绪，后故事**：读者读完要“爽 / 意难平 / 后背发凉”，不是“文笔真好”。
2. **一个核心支点撑一篇**：不做多线、不铺世界观、不靠设定解释续命。
3. **每句话必须有用**：不推动剧情、不铺垫反转、不推高情绪的句子，删。
4. **反转要公平**：可以误导，不能对读者撒谎；至少两处伏笔，揭示后必须结算。
5. **去 AI 味不是去人味**：保留叙述者的偏见、生活噪音、身体代价和留白；不靠错别字、脏话、碎句伪装。

## 不做什么

- 不洗稿、不抄句子和情节链。
- 不承诺“绕过 AI 检测”或“100% 过稿”。
- 不把检查器分数当成平台审核结果。
- 不把所有人的文字改成同一种“人味模板”。
- 不冒充“读过 1000 本全文”；没有索引就说种子库，不编书名和引文。
