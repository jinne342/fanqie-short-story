# 运行环境与模型适配

> 用途：同一个 skill 在不同 Agent、聊天模型、API 里跑，先判断“有什么工具、多少上下文、单次能输出多少”，再决定怎么写。
> **不要靠猜模型名字**；只依据可观察的能力。

## 0. 先探测四件事

| 能力 | 怎么判断 | 影响 |
|---|---|---|
| 读文件 | 能否打开 `references/` | 能，则渐进加载；不能，则把关键规则内联 |
| 跑命令 | 能否执行 `python` | 能，则跑 `check_ai.py`；不能，则用手工清单 |
| 写文件 | 能否保存 `正文.md` | 能，则分节落盘；不能，则分段输出 |
| 输出上限 | 单次能写多少字 | 1.8 万字必须分 6–9 次，不要一次吐完 |

先做一次能力判断，再选下面的运行形态。判断错了，后面全是白费。

## 1. 四种运行形态

### A. Agent + 工具（DSH / Claude Code / Codex / 其他本地 Agent）

- 读 `SKILL.md` → 按阶段读 `02` → `03` → `04`，不要一次读全部。
- 分节写，落到 `正文.md`；每写完一节跑一次 `check_ai.py`，只改阻断项。
- 路径示例：DSH `~/.dsh/skills/fanqie-short-story`；Claude Code `.claude/skills/...`；项目级 `.dsh/skills/...`。
- 只用脚本的真实输出，不伪造分数；没有跑就说“未跑”。

### B. 聊天 + 文件上传（ChatGPT / Claude 网页）

- 不能跑脚本；用 `prompt.md` + `04-checklist.md` 的手工清单。
- 让用户把正文贴回对话；分节输出，每节末尾自查 5 条。
- 不声称“扫描器通过”；可以说“按手工清单检查，还有 X 处需要改”。

### C. 纯聊天（无文件、无工具）

- 先问三件事：主情绪、题材、目标字数；给 7 拍大纲，确认后再写。
- 每次输出 1500–2500 字；停下来让用户回“继续”，不要硬挤成一次。
- 结尾给手工质检表，不报 0–100 分。

### D. API 流水线

- 生成 call → 本地 `check_ai.py` → 定向改写 call；两次 prompt 分离。
- 不要在生成 call 里塞“边写边检查”；检查会抢走故事的注意力。
- 改写 call 只允许改报告里的阻断项，不允许改人物动机和关键证据。

## 2. 上下文预算

| 文件 | 大小（约） | 什么时候读 |
|---|---|---|
| `SKILL.md` | 11 KB | 每次必读 |
| `references/01-platform-2026.md` | 8 KB | 涉及签约、字数、红线时 |
| `references/02-craft.md` | 17 KB | 构思、搭节拍、写开篇/反转/结尾时 |
| `references/03-deslop.md` | 18 KB | 去 AI 味、改稿时（核心） |
| `references/04-checklist.md` | 7 KB | 终检、诊断时 |
| `references/05-runtime-adapters.md` | 6 KB | 换环境/模型时 |
| `examples/case-01/` | 5 KB | 想看对照时 |

**最小加载**：`SKILL.md` + `03`（只改稿）。
**写新篇**：`SKILL.md` + `02` + `03`。
**诊断**：`SKILL.md` + `04` + `03`。
**平台问题**：加 `01`。
不要一次把 60 KB 全读；先读标题和“什么时候读”，再决定。

## 3. 输出上限与分节

1.8 万汉字不可能在一次回复里稳定写完。按 6–9 节，每节 1500–2200 字：

- 每节一个 POV、一个主问题、一次变盘；
- 每节结尾留一个具体钩子，下一节开头接上；
- 维护一张**连续性表**：谁在哪、伤在哪、第几声铃、情感值、谁还不知道什么；
- 单次输出上限低于 2000 字时，每轮写 800–1200 字，让用户回“继续”；
- 不要为了“一次写完”压缩全文，压完一定崩节奏。

## 4. 模型差异

- **推理型模型**：容易过度规划。把大纲控制在一页内，然后开始写；不要在脑内推演全文。
- **快速/非推理模型**：需要更明确的清单和节拍表；每节写完立刻对照 `04`。
- **长上下文模型**：也不要一次塞全部参考；注意力会稀释，先读当前阶段需要的。
- **小上下文模型（8K 左右）**：只用 `prompt.md`，一次写一节；把连续性表放在对话最上面。
- **模型身份**：不要在 skill 里写“你是 DeepSeek / Claude / GPT”的长篇自我描述；模型会换，身份描述会过期。写“你能做什么、不能做什么”，不写“你是谁”。

## 5. 路径与命令

Windows PowerShell：

```powershell
$py = "python"   # 没有就试 py / python3
& $py "C:\path\to\fanqie-short-story\scripts\check_ai.py" "C:\path\to\正文.txt" --min-words 6000
```

- 路径有中文或空格时，一定加引号。
- DSH 用户技能根：`$env:DSH_HOME\skills`（默认 `~/.dsh/skills`）。
- 项目级技能根：`<project>/.dsh/skills`。
- Claude Code：`.claude/skills/`；其他 Agent 看它自己的文档。
- 不要假设 `python` 一定存在；`python`、`py`、`python3` 依次试。

## 6. 失败处理

- **没有 Python**：走手工清单，明确说“未完成机器扫描”。
- **不能写文件**：用带文件名的代码块输出，让用户自己保存。
- **没有工具**：直说“这个环境跑不了脚本”，不要编造分数。
- **上下文快满**：只保留连续性表、当前节、下一节钩子；不要重贴全文。
- **平台规则不确定**：读 `01` 的可靠度标注，提醒用户以作家助手后台为准。

## 7. 反模式

- 不在 skill 里堆“本模型支持 1M 上下文，所以可以一次写 1.8 万字”；输出上限和注意力是两回事。
- 不把环境说明写成产品广告；只写可操作的差异。
- 不伪造“已跑扫描器”“已通过检查”。
- 不因为换了模型就改故事核、人物动机和关键证据。
- 不把“环境适配”写成又一篇方法论；它只是一张能力对照表。
